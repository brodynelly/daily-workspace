A calmer home for your day.

A Mac-first workspace for today's notes, tasks, and calendar agenda—quick to capture in, respectful of your Obsidian vault, and smooth without demanding motion.

Product decision

Build a small, standalone Mac companion—not a Luuna feature. Use SwiftUI for the native shell, Markdown files in the selected Obsidian vault for notes, EventKit for a read-only Apple Calendar agenda, and local app storage for the app's own tasks.

“Raycast Notes-inspired” means fast invocation, compact hierarchy, and keyboard-first capture. It does not mean copying Raycast's branding or exact UI. “Neovide-inspired” means optional smooth motion in the app's own editor caret and restrained transitions. Neovide's editor cursor is not the macOS pointer; do not replace the system pointer or promise a pixel-perfect renderer match.

Product promise

Open one screen and know what is next, what needs doing, and where to write today's note.

Non-goals for MVP

No cloud account, custom sync, AI, full Obsidian replacement, Reminders integration, calendar editing, or global cursor trail.

Core experience

Today

Upcoming agenda, today's tasks, daily-note open/edit action, and one-step quick capture.

Notes

Open or create the dated Markdown note in the user-selected vault. Keep Obsidian as the home for the wider knowledge base.

Tasks

Small local inbox and today's list. Add, edit, complete, reopen, and optionally link a task to a note.

Calendar

Read-only agenda via EventKit. Permission can be denied without blocking notes or tasks.

Architecture & safety

Native shell

SwiftUI screens and native controls. Bridge to AppKit selectively only for a demonstrated need. Decide the minimum macOS version before implementation; confirm EventKit APIs and signing/entitlements against it.

Vault access

Let the user choose a vault through the system picker. Retain only scoped access needed by the app. A moved or revoked vault is an explicit recoverable state, never a reason to write elsewhere.

Markdown safety

Start with a configurable daily-note folder/name. Proposed default: YYYY-MM-DD.md at the vault root. Prefer standard relative Markdown links for new links; preserve wikilinks, frontmatter, embeds, attachments, and unknown syntax.

Conflict safety

Before save, detect if the file changed outside the app. On conflict, stop and offer reload/compare/recoverable copy. Never silently overwrite. Use atomic saves where practical.

Calendar permission

Request event access only when the feature is enabled. For macOS 14+ full event access, verify the usage description and EventKit API; sandboxed apps also need the Calendar entitlement. Denied/revoked access remains a normal state.

Privacy

Core use works offline. No telemetry or uploads of notes, event details, or task titles. Avoid content in logs; keep permissions narrow; do not reorganize or bulk-rewrite the vault.

Polish without sacrificing control

  • Use brief, restrained transitions for view changes, panel expansion, and task completion.
  • Start with the native text caret. Prototype spring-like caret interpolation only if it preserves insertion, selection, undo, IME composition, dictation, and accessibility behavior.
  • Respect macOS Reduce Motion. Keep every action and state understandable when all nonessential motion is removed.
  • An in-app motion setting may offer system default / reduced / on, but must never override a system Reduce Motion request with more motion.
  • Keep keyboard focus visible, provide VoiceOver labels, and never encode task/event state by color alone.

Build sequence

0

Resolve the product choices

Choose app name, minimum macOS, distribution/sandbox model, daily-note folder/template, task persistence approach, and whether quick invocation means an in-app panel or a global shortcut.

1

Prove a local vertical slice

Build the Today shell and app-managed tasks. Add a chosen vault, daily Markdown open/create/edit/save, scoped access persistence, restart handling, and external-change detection. Do not add Calendar yet.

2

Add read-only Calendar

Integrate EventKit with just-in-time permission, denial/revocation states, event refresh, all-day events, timezone and daylight-saving tests. Keep all Calendar records read-only.

3

Polish and accessibility

Add keyboard-first quick capture, validate VoiceOver and Reduce Motion, then prototype optional motion. Measure launch/idle behavior on real supported Macs; remove effects that impair typing or clarity.

4

Run a real-vault pilot

Exercise external edits, sync changes, moved vaults, permissions, restart, and daily use. Decide separately whether Reminders, search, calendar writes, sync, or another platform earns a later phase.

Definition of a safe first release

  • Launches without requiring a vault, account, Calendar permission, or network.
  • Opens/creates today's note only in the selected vault and preserves Markdown content it does not understand.
  • Detects a conflicting external edit and does not silently overwrite it.
  • Tasks survive app restart and remain clearly app-owned rather than presented as Reminders.
  • Read-only agenda handles access denied/revoked, empty calendars, all-day events, timezone/day boundaries, and event-store changes.
  • Calendar failure does not block notes/tasks; empty data is distinguished from unavailable data.
  • Keyboard-only, VoiceOver, and Reduce Motion paths remain functional.
  • Private content is not logged or transmitted; entitlements and privacy prompts match the features used.
  • Unit tests cover task state/persistence, date templates, Markdown conflict handling, permission states, and timezone edges; a real Mac smoke validates native permissions, file access, restart, and accessibility.

Research basis

Platform and ecosystem documentation supports the integration paths below; recommendations about MVP scope, conflict handling, and visual direction are product judgments, not benchmark results. No evidence establishes that SwiftUI is faster than Tauri for this workload or that Neovide-like animation improves usability.
